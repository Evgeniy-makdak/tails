# Интеграция TK919 4G ↔ приложение Tailio («Хвостик»)

Источник по железу: `docs/Инструкция для трекера TK919 4G.pdf` (Winnes GPS / mytkstar.net + SMS-команды).

**Вердикт:** TK919 подходит для продукта лучше, чем закрытые consumer-ошейники без `adminip`. Трекер **можно перенаправить на наш сервер** SMS-командой и больше не зависеть от приложения Winnes.

---

## 1. Что даёт инструкция (факты)

| Возможность | Как | Для Tailio |
| --- | --- | --- |
| SIM Micro + 4G/GPRS | МТС / Мегафон, PIN off, интернет без блокировки | Обязательно |
| Live / история / геозоны | Через **Winnes GPS** → `www.mytkstar.net` | Их app — только для первичной проверки железа |
| Смена сервера | `adminip123456 <ip\|host> <port>` | **Ключ интеграции** |
| APN | `apn123456 <apn>` (+ user/pass) | Нужно под оператора SIM |
| Интервал точек | `upload123456 <сек>` | Live / эконом / SOS |
| Координаты по SMS | `g123456#` | Диагностика, не продукт |
| Admin-телефон | `admin123456 +79…` | Только ваш номер шлёт команды |
| Статус | `check123456` | Диагностика IP/APN/GPS |
| Заводской сервер (из PDF) | `47.112.97.221:30039`, пример `gpstar.ru:8002` | Backup, если нужно вернуть в их облако |

Пароль по умолчанию: **`123456`** (если не меняли).

Приложение вендора **не обязательно** для прода: оно лишь UI к их облаку. Наш путь — **свой приём телеметрии**.

## 2. Архитектура (целевая)

```
┌──────────────┐  SMS adminip     ┌─────────────────────────────┐
│ TK919 4G     │ ───────────────►│ Приёмник протокола          │
│ GPS + LTE    │  TCP (GPRS)     │ Traccar / Tailio-TCP         │
└──────────────┘                 └──────────────┬──────────────┘
                                                │ webhook / API
                                                ▼
                                 ┌──────────────────────────────┐
                                 │ Tailio backend (Render)      │
                                 │ last_location + /api/tracks  │
                                 └──────────────┬───────────────┘
                                                │ HTTPS poll
                                                ▼
                                 ┌──────────────────────────────┐
                                 │ App Tailio                   │
                                 │ LOCATION_MODE=api            │
                                 └──────────────────────────────┘
```

Почему не «TCP сразу на Render Free»:

- Render Free отдаёт **HTTP(S)**, не произвольный TCP-порт протокола трекера.
- TK919 шлёт **бинарный/текстовый TCP-протокол** (часто **Watch** или **GPS103** — зависит от прошивки 4G), а не JSON на `/api/...`.

Поэтому пилот:

1. **Traccar** (Docker на VPS с открытым TCP) **или** GPS-Trace (уже знает TK-Star TK919-4G) принимают протокол.
2. Tailio забирает точку (webhook / REST) и отдаёт приложению уже знакомый JSON.

Долгосрок: свой TCP-listener на VPS рядом с Tailio — без посредника.

## 3. Протокол: что выяснить на первом подключении

Разные источники для «TK919» указывают **GPS103** (ASCII `imei:…;`) или **Watch** (`[SG*id*…]`). У **TK919-4G** чаще встречается Watch.

**Правило:** не гадать — один раз снять сырой лог:

1. Поднять Traccar, открыть порт 5001 (и при необходимости 5093).
2. SMS: `adminip123456 <IP_VPS> 5001`.
3. Смотреть `tracker-server.log`: текст `imei:` → GPS103; `[SG*` → Watch.
4. В Traccar создать устройство с нужным протоколом / портом и ID с наклейки корпуса.

ID в Tailio = ID с корпуса / IMEI (то, что принимает сервер).

## 4. Пошаговый запуск железа (сегодня)

С телефона-админа на номер SIM в трекере:

```text
1) apn123456 internet.mts.ru          # APN оператора (пример МТС)
2) admin123456 +79XXXXXXXXX           # ваш номер = admin
3) timezone123456 +3
4) upload123456 60                    # раз в 60 с (пилот)
5) check123456                        # убедиться: сеть, GPS, IP
```

Проверка в их экосистеме (опционально, 10–15 мин):

- Winnes GPS / `https://www.mytkstar.net/` → ID с наклейки → live на карте.
- Если live есть — железо и SIM ок. Дальше переключаем IP на наш стек.

Вернуть в их облако при сбое:

```text
adminip123456 47.112.97.221 30039
```

(из инструкции; ответ `SET IP OK` / `adminip ok`).

## 5. Пошаговая интеграция в Tailio (разработка)

### Этап A — контракт API (делаем в репозитории)

Уже целевой клиентский контракт (`src/api/collar.ts`):

```http
GET /api/collars/{collarId}/location?petId=...
```

Добавляем на бэкенде:

| Метод | Назначение |
| --- | --- |
| `POST /api/collars/:id/telemetry` | Приём точки (адаптер / curl / webhook) |
| `GET /api/collars/:id/location` | То, что читает `LOCATION_MODE=api` |
| `POST /api/collars/bind` | Связь `collarId` ↔ `userId` / `petId` (след. итерация) |

Заголовок ingest: `X-Collar-Ingest-Key` = секрет из env (`COLLAR_INGEST_SECRET`).

### Этап B — приёмник протокола

**Рекомендация пилота:** Traccar в Docker на VPS (~€5/мес):

```bash
# пример
docker run -d --name traccar -p 8082:8082 -p 5001-5150:5001-5150 \
  -v traccar-data:/opt/traccar/data traccar/traccar:latest
```

1. Создать device = ID TK919.
2. SMS: `adminip123456 <IP_VPS> <порт_протокола>`.
3. Дождаться первой позиции в Traccar.
4. Включить Forwarding / webhook на  
   `https://<tailio>/api/collars/<id>/telemetry`  
   или короткий адаптер `server/src/traccarForward.js`, который мапит Traccar JSON → наш DTO.

**Альтернатива без VPS:** GPS-Trace (устройство в каталоге) → их API → наш адаптер. Быстрее старт, зависимость от их SLA.

### Этап C — приложение

1. В профиле питомца сохранить реальный `collarId` (ID с корпуса).
2. `EXPO_PUBLIC_LOCATION_MODE=api`.
3. Карта / геозоны / запись прогулки читают точку ошейника, не GPS телефона.
4. Онбординг «Подключить ошейник»: ввод ID + инструкция SMS (вместо BLE-поиска рядом).

### Этап D — команды из Tailio

| Действие в app | Канал к TK919 |
| --- | --- |
| Частый live (прогулка / SOS) | SMS `upload123456 30` или GPRS-команда через Traccar |
| Эконом | `upload123456 600` |
| LED (если есть в прошивке) | Команда из Winnes «LED mode» → найти SMS/GPRS эквивалент после sniff |
| Звонок / monitor | `monitor123456` / `tracker123456` |
| Координаты offline | `g123456#` (fallback) |

Для SMS из бэкенда нужен SMS-шлюз (SMS.ru / Twilio) на admin-логике **или** обратный канал GPRS через Traccar custom command.

Геозоны на первом этапе оставляем **на стороне Tailio** (уже есть в app): точка пришла → проверка полигона → звук/пуш. Дублировать «Территория контроля» Winnes не нужно.

## 7. Ограничения и риски

| Риск | Митигация |
| --- | --- |
| Протокол Watch vs GPS103 | Sniff в Traccar при первом `adminip` |
| Render без TCP | Traccar/VPS или GPS-Trace как фронт |
| Эфемерный диск Render Free | `last_location` в JSON ок для пилота; прод → Postgres |
| SIM без data / неверный APN | Чеклист SMS + `check123456` |
| Пароль 123456 | Сменить после пилота; не светить в git |
| LED/buzzer без SMS в PDF | Проверить в Winnes «LED режим», затем вытащить GPRS-команду из лога Traccar |

## 8. Чеклист «готово к карте в Tailio»

- [ ] SIM online, PIN off, APN задан, `check123456` ок  
- [ ] Live виден хотя бы раз (Winnes или Traccar)  
- [ ] `adminip` указывает на наш приёмник  
- [ ] `POST .../telemetry` пишет точку в Tailio  
- [ ] `GET .../location` отдаёт lat/lng  
- [ ] В app `LOCATION_MODE=api` и верный `pet.collarId`  
- [ ] Маркер на карте двигается с ошейником на улице

## 9. Порядок работ команды (я веду)

1. Документ + API `telemetry` / `location` в репозитории.  
2. Поднять Traccar (или GPS-Trace) и переключить TK919 SMS `adminip`.  
3. Адаптер webhook → Tailio.  
4. Привязка ID в профиле + `LOCATION_MODE=api`.  
5. Команды upload/SOS + (по возможности) LED.  
6. Автосэмпл точек в `/api/tracks` без GPS телефона.

*Обновлять этот файл по мере появления реального лога протокола с вашего экземпляра TK919.*
