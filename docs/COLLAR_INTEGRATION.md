# Ошейник с GPS + SIM ↔ приложение «Хвостик» (Tailio)

Документ описывает **симбиоз железа и приложения**: что уже сделано в прототипе, как должен работать продакшен с ошейником, куда уходят координаты, и какие готовые трекеры рассматривать.

Связанные материалы:

- схема в корневом [README.md](../README.md) (раздел «Симбиоз с ошейником»);
- деплой бэка: [DEPLOY_BACKEND.md](DEPLOY_BACKEND.md);
- живой чат: [CHAT_GUIDE.md](CHAT_GUIDE.md);
- заготовка клиента: `src/api/collar.ts`, `src/location/providers/apiCollar.ts`.

---

## 1. Главная идея

Ошейник — **самостоятельное устройство**. Он:

1. определяет координаты по спутникам (GPS / GNSS);
2. передаёт их в интернет через **встроенную SIM / eSIM** (LTE / Cat-M / NB-IoT);
3. **не** общается с телефоном хозяина напрямую для live-трекинга на расстоянии.

Приложение «Хвостик» **не «подключается к чипу GPS»**. Оно читает уже сохранённые данные с **облачного API** (ваш бэкенд Tailio или API производителя ошейника).

```
┌─────────────────────┐     мобильная сеть      ┌──────────────────────────┐
│  Ошейник            │ ───────────────────────►│  Облако                  │
│  GPS + модем + SIM  │   HTTPS / MQTT          │  вендор  ИЛИ  Tailio     │
└─────────────────────┘                         └────────────┬─────────────┘
                                                             │ HTTPS / WS
                                                             ▼
                                                    ┌────────────────┐
                                                    │  Приложение    │
                                                    │  «Хвостик»     │
                                                    └────────────────┘
```

Телефон хозяина может быть в другом городе — точка на карте всё равно обновляется, пока у ошейника есть покрытие сети и заряд.

## 2. Нужна ли SIM-карта?

**Да**, если продукт обещает «вижу питомца всегда, даже когда я далеко».

| Канал | Когда хватает | Ограничение |
| --- | --- | --- |
| **SIM / eSIM (LTE, Cat-M1, NB-IoT)** | Live-карта, геозоны, SOS на расстоянии | Нужна подписка / IoT-тариф; расход батареи |
| **Только Bluetooth / BLE** | Синхронизация рядом с телефоном | Без телефона рядом — нет live |
| **GPS без сети** | Лог в памяти ошейника | Точки появятся только после выгрузки |

GPS даёт координаты; **SIM даёт способ их отправить**. Без радиоканала в интернет приложение не узнает, где пёс.

---

## 3. Куда передаются координаты?

Ошейник **не отдаёт публичный API «в себя»**. Типичный поток:

1. Ошейник → **сервер** (вендора или ваш Tailio).
2. Сервер сохраняет `last_location` (+ опционально историю точек).
3. Приложение периодически запрашивает точку **у сервера** (или получает push/WebSocket).

### Вариант A — облако производителя ошейника

```
Ошейник → API вендора → (адаптер на Tailio) → приложение
```

Плюс: железо и связь уже решены. Минус: зависимость от их подписки, ToS, и часто **нет официального партнёрского API** (только reverse-engineering — рискованно для прода).

### Вариант B — ваш бэкенд Tailio (целевой для продукта)

```
Ошейник → POST https://<ваш-api>/api/collars/.../telemetry
Tailio сохраняет точку / трек
Приложение → GET /api/collars/{id}/location  (+ уже есть /api/tracks)
```

В коде клиента уже заложен контракт (пока endpoint не задеплоен → fallback):

```http
GET /collars/{collarId}/location?petId=...
```

Ожидаемый JSON (см. `src/api/collar.ts`):

```json
{
  "petId": "pet-1",
  "collarId": "collar-42",
  "latitude": 59.9362,
  "longitude": 30.3141,
  "accuracyM": 12,
  "batteryPercent": 67,
  "online": true,
  "updatedAt": "2026-09-30T19:00:00.000Z"
}
```

Включение на клиенте: `EXPO_PUBLIC_LOCATION_MODE=api`.

## 4. Что сделано в прототипе сейчас

### Приложение (клиент)

| Возможность | Как работает сегодня |
| --- | --- |
| Карта | OpenFreeMap + MapLibre |
| Live-точка | GPS **телефона** (`LOCATION_MODE=device`) — заглушка ошейника |
| Геозоны | Создание / правка / удаление; звук при выходе из безопасной / входе в опасную |
| Прогулка | Кнопки «Начать» / «Завершить» → точки с телефона → `POST /api/tracks` |
| История | Список треков с сервера, полилиния, удаление одной / всех |
| Чат | Live WebSocket на Render |
| Аккаунты приложения | Локально (AsyncStorage), не на сервере |
| Провайдер ошейника | `apiCollar.ts` готов читать API, но бэкенд endpoint ещё не принимает телеметрию от железа |

### Бэкенд (Render Free: `tailio-chat.onrender.com`)

| API | Назначение |
| --- | --- |
| Чат `/api/...`, `/ws` | Пользователь ↔ консультант |
| `GET/POST/DELETE /api/tracks` | История прогулок (лимит ≤12 треков, ≤120 точек) |
| Кабинет консультанта | PWA на том же хосте |

**Ещё нет на сервере:** приём телеметрии от ошейника, `last_location`, привязка `collarId` ↔ пользователь, команды LED/buzzer, постоянный диск (на Free данные могут сбрасываться при redeploy).

### Важно про текущую «прогулку»

Сейчас маршрут пишется с **телефона хозяина**. В проде с ошейником логичнее:

- ошейник сам шлёт точки на бэкенд постоянно (или в режиме «прогулка / live»);
- приложение только отображает историю;
- кнопка на карте может включать «частый режим» на ошейнике, а не писать GPS телефона.

## 5. Целевое взаимодействие (как должно быть на проде)

### 5.1. Привязка устройства

1. Хозяин в онбординге / профиле вводит ID ошейника (QR / IMEI / код из коробки).
2. Tailio сохраняет связь: `userId` ↔ `petId` ↔ `collarId`.
3. Ошейник аутентифицируется на сервере (device token / сертификат / shared secret от завода).

### 5.2. Live на карте

1. Ошейник раз в N секунд (например 15–60 с; в SOS — чаще) шлёт телеметрию.
2. Сервер обновляет `last_location`.
3. Приложение с `LOCATION_MODE=api` опрашивает `GET /collars/{id}/location` или подписывается на WebSocket.
4. Маркер и геозоны работают от этой точки (не от GPS телефона).

### 5.3. История перемещений

1. Сервер копит точки (или сэмплирует: не чаще чем раз в X метров / секунд).
2. Ночью / по запросу собирает «прогулки дня» в `walks` (тот же `/api/tracks`).
3. Экран «История» рисует полилинии без участия телефона хозяина.

### 5.4. SOS / свет / звук

1. Хозяин жмёт SOS в приложении.
2. Приложение → API Tailio → (адаптер вендора или прошивка) команда ошейнику: live-tracking + LED + buzzer.
3. Частота GPS на ошейнике повышается, пока идёт поиск.

### 5.5. Консультант

Чат уже на том же бэкенде: оператор может видеть последнюю точку питомца (когда появится `last_location` в API), не требуя отдельного «ошейникового» кабинета.

## 6. Дальнейшие шаги (roadmap)

Порядок разумный для команды без своей фабрики железа:

### Этап 1 — контракт на бэкенде (без железа)

1. `POST /api/collars/:id/telemetry` — приём точки (пока можно слать curl / скрипт).
2. `GET /api/collars/:id/location` — то, что уже ждёт клиент.
3. Хранение `last_location` + опционально append в активный трек.
4. Переключить демо на `LOCATION_MODE=api` и проверить карту/геозоны.

### Этап 2 — пилот на готовом трекере

1. Выбрать устройство (см. §7).
2. Написать **адаптер** Tailio ↔ облако вендора (или MQTT/HTTP от OEM).
3. Привязка `collarId` в профиле питомца.
4. Автотреки в `/api/tracks` без кнопки «Начать» с телефона (кнопку оставить как «режим прогулки»).

### Этап 3 — прод-инфраструктура

1. Постоянная БД (Postgres), не эфемерный JSON на Render Free.
2. Серверные аккаунты приложения + привязка устройств.
3. Push-уведомления о геозонах / SOS.
4. Биллинг SIM / подписки (если white-label OEM).
5. Нативные сборки App Store / Google Play (фон и push надёжнее, чем PWA).

### Этап 4 — свой/OEM ошейник (опционально)

Если нужен бренд «Хвостик» на корпусе: OEM с вашей прошивкой, которая шлёт **сразу на Tailio**. Дольше и дороже, но полный контроль формата и данных.

## 7. Подходящие варианты ошейников / трекеров

> Это **обзор рынка для выбора пилота**, не реклама и не оферта.  
> Перед закупкой уточняйте: покрытие в РФ/СНГ, наличие **официального B2B API**, условия подписки, возможность LED/buzzer по команде.  
> У большинства consumer-брендов **публичного партнёрского API нет** — интеграция либо через официальный договор, либо через непрозрачный reverse-engineering (для прода «Хвостик» второй путь нежелателен).

### 7.1. Consumer GPS с встроенной SIM (быстрый пилот UX)

| Устройство | Связь | Что даёт | Для Tailio |
| --- | --- | --- | --- |
| **[Tractive](https://tractive.com/)** (DOG / CAT) | Встроенная SIM, LTE / Cat-M, 175+ стран | Live GPS, история, LED, buzzer, live-режим, активность/health в новых моделях | Самый зрелый consumer-класс; **официального публичного API нет**. Есть неофициальные клиенты (community) — только для исследований. Для продукта нужен **B2B-договор с Tractive** или отказ от прямой интеграции |
| **[Weenect](https://www.weenect.com/)** | GSM/LTE + подписка | Live, история, звук/вибрация на части моделей | Аналогично: облако закрытое, community reverse-API есть, для прода — только партнёрство |
| **Invoxia / другие EU-трекеры** | SIM + подписка | Похожий UX | Уточнять API индивидуально |

**Вывод:** для «просто пощупать UX карты» можно купить Tractive/Weenect как эталон железа. Для **встраивания в Tailio** без юридической интеграции — не опираться на неофициальные API.

### 7.2. OEM / white-label GPS-ошейники (рекомендуется для своего продукта)

Ищите фабрики/бренды с формулировками *pet GPS tracker OEM*, *white label*, *MQTT/HTTP telemetry*, *open API*:

| Подход | Плюсы | Минусы |
| --- | --- | --- |
| **OEM модуль** (корпус + ваша прошивка или их SDK) | Данные сразу на Tailio; свой бренд; контроль формата | MOQ, сертификация (ЕАС/CE), логистика SIM, поддержка |
| **White-label готовый трекер** с их облаком + API ключ для партнёров | Быстрее старт | Зависимость от их SLA и цен |
| **Industrial IoT tracker** (не «ошейник», а компактный GPS+LTE на ошейник/шлейку) | Часто есть нормальный MQTT/HTTP API | Нужен корпус/крепление «для питомца», вес, батарея |

Практичный путь для «Хвостик»:

1. Короткий список 2–3 OEM в Китае/EU с sample 1–5 шт.  
2. Требование в ТЗ: **HTTPS POST или MQTT** на ваш URL, JSON как в §3, команды LED/buzzer.  
3. eSIM или пластиковая SIM с IoT-тарифом, покрывающим ваш рынок.

### 7.3. Что не путать с GPS-ошейником

| Тип | Почему не замена |
| --- | --- |
| **Apple AirTag / Tile / Samsung SmartTag** | Сеть чужих телефонов, нет своей SIM, нет гарантированного live «где угодно» |
| **Обычный Bluetooth-ошейник без LTE** | Работает только рядом с телефоном |
| **Ошейник только с вибро/антилай** | Нет координат |

### 7.4. Рекомендация под текущий этап Tailio

| Цель | Что брать |
| --- | --- |
| Проверить UI карты/геозон/SOS без железа | Как сейчас: `LOCATION_MODE=device` |
| Пилот «настоящий live с улицы» без своей фабрики | Consumer (Tractive и т.п.) **вручную** как референс + параллельно Этап 1 API на Tailio; либо OEM sample с HTTP на ваш сервер |
| Продукт «Хвостик» со своим брендом | **OEM + ваш бэкенд (вариант B)**; consumer-бренды — только если есть официальный партнёрский API |

## 8. Чеклист при разговоре с поставщиком ошейника

Спросите письменно:

1. Есть ли **официальный** REST/MQTT API для партнёров (не только ваше мобильное приложение)?  
2. Может ли устройство слать телеметрию **на наш URL** (не только в их облако)?  
3. Формат: lat, lng, time, battery, online, collarId?  
4. Команды: LED, buzzer, увеличить частоту GPS?  
5. Покрытие сети в нужных странах / регионах РФ?  
6. Кто платит за SIM и как устроена подписка?  
7. Гарантия, сертификация, вес, IP-защита, время работы батареи в live-режиме.
